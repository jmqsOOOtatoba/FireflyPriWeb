# 全站视觉移植复刻：把 Firefly 改造成 animal-island-ui 风格的七期工程（含复刻清单与踩坑全录）

2026-10-11 至 10-12，本博客完成了一次全站视觉移植：从原有主题换成 [animal-island-ui](https://github.com/guokaigdg/animal-island-ui)（治愈系海岛风格 React 组件库）的设计语言。**22 个文件修改（+275/−73 行）+ 6 个字体文件 + 33 份参考规范**，功能零损失。

本文写给两类读者：

- **未来的维护者（包括新会话的 AI 助手）**：读完应知道每一期改了哪些文件、为什么、精确色值在哪、验证基线是多少、哪些坑已经踩过；
- **想复现的访客**：文末「复刻清单」从零列出全部步骤，所有关键代码在正文中可照抄。

---

## 〇、决策：为什么不引库、也不从零重写

起因是想把博客「完全变成 animal-island-ui 的风格」。三条路线对比后选了**风格移植**：

| 路线 | 结论 | 原因 |
|---|---|---|
| 直接安装它的 React npm 包 | ❌ | 本博客是 Astro 7 + Svelte 5 岛屿，混入 React 运行时得不偿失；且库里没有文章卡、目录、归档等博客部件 |
| **移植它的设计规范到现有站点** | ✅ | 风格 = CSS + design token，可整体搬运；内容、友圈、发布台、评论、搜索、性能优化成果全部保留 |
| 按它的风格从零重写博客 | ❌ | 功能与内容全部归零，按月计的工程量 |

关键依据：**项目作者自己为「不装库只抄风格」留了官方通道**——`docs/design-system/css-variables.md` 第一句就是 "When re-implementing the style without depending on the component library, declare the following variables on `:root`"。README 里那条 `import 'animal-island-ui/style'` 规则是**库使用者**的须知，不装库时不仅不适用（没有它的组件需要被样式化），而且不该引（会把整套 reset 和组件类灌进 Tailwind 体系打架）。

暗色模式：用户明确**不做**，所有改造只管亮色（涉及暗色的规则都用 `:root:not(.dark)` 或原样保留）。

## 一、准备工作：把规范拉到本地

风格复刻的「唯一真相源」是仓库里的两处：

1. **技能包** `skills/animal-island-ui-style/`（SKILL.md 中英双语 + 13 份组件 props 参考）
2. **设计系统** `docs/design-system/`（design-tokens.md 精确值、design-rules.md 七律与 16 条反模式、components/ 逐组件像素级 CSS）

本机 `raw.githubusercontent.com` 直连不稳，**用 api.github.com 的 contents 接口拿 base64 再解码**最稳，一个 Node 脚本批量拉：

```js
// 拉取单个文件：GET https://api.github.com/repos/<owner>/<repo>/contents/<path>
// 返回 JSON 的 content 字段即 base64，解码写盘即可
const res = await fetch(url, { headers: { Accept: "application/vnd.github+json" } });
const json = await res.json();
await writeFile(dest, Buffer.from(json.content, "base64").toString("utf8"));
```

共下载 33 个文件，落在 **`docs/animal-island-ui-style/`**（含 `design-system/` 子目录）。本站后续所有色值都以这份本地规范为准，动样式前先查它。

技能包里 14 条「硬规则」中真正管视觉的核心几条：

1. 不用纯黑文字（`#000`/`#111`），不用冷灰背景（`#fafafa`/`#f5f5f5`）
2. 交互元素圆角 ≥ 12px，按钮和输入框一律 **50px pill**
3. **3D 堆叠阴影（`0 5px 0 #bdaea0`）只属于 primary 按钮**，default 类只用柔和抬升影
4. 字体圆体（Nunito + Noto Sans SC），字重 body 500、标题 600–900，永不低于 400
5. 动效统一 `cubic-bezier(0.4, 0, 0.2, 1)`，时长 0.15–0.35s
6. 焦点环：输入类黄色 `#ffcc00`、按钮薄荷 `#19c8b9`，绝不用冷蓝

核心 token（完整值见本地 `design-system/css-variables.md`）：

```css
:root {
  --animal-primary: #19c8b9;        /* hover #3dd4c6 / active #11a89b */
  --animal-text: #794f27;            /* 标题/主文字（大地棕） */
  --animal-text-body: #725d42;       /* 正文 */
  --animal-text-secondary: #9f927d;  /* 次级 */
  --animal-bg: #f8f8f0;              /* 页面底（羊皮纸） */
  --animal-bg-content: rgb(247, 243, 223); /* 卡片/内容区（奶油） */
  --animal-border: #c4b89e;
  --animal-radius: 18px;  --animal-radius-pill: 50px;
  --animal-shadow-btn: #bdaea0;      /* 3D 堆叠色 */
  --animal-ease: cubic-bezier(0.4, 0, 0.2, 1);
}
```

### 二期：按钮系统（11 文件）

**关键机制（复刻必读）**：`main.css` 里 `.btn-*` 原有规则都在 `@layer components`（161–619 行的大块）内，而模板里散落的 `rounded-lg` 等是 utilities 层——**层序上 utilities 永远赢**。所以按钮的 pill 化规则**刻意写在文件末尾、不进任何层**：未分层的 normal 声明在级联里排最后，无条件压过所有分层规则。

```css
/* main.css 末尾（未分层）—— animal-island 二期·按钮系统 */
.btn-plain, .btn-regular, .btn-card {
  border-radius: 50px;              /* 硬规则：按钮一律 pill */
  transition:
    background-color 0.15s var(--ease-standard),
    color 0.15s var(--ease-standard),
    box-shadow 0.2s var(--ease-standard),
    transform 0.15s var(--ease-standard),
    opacity 0.15s var(--ease-standard);
}
/* default 填充按钮：柔和抬升投影 rest → hover 加深 */
.btn-regular, .btn-card { box-shadow: 0 2px 4px 0 rgba(61,52,40,0.06); }
.btn-regular:hover, .btn-card:hover { box-shadow: 0 3px 10px 0 rgba(61,52,40,0.1); }
/* ghost 按钮透明底不投影，hover 填底后再给，避免浮出脏晕 */
.btn-plain:hover { box-shadow: 0 2px 4px 0 rgba(61,52,40,0.06); }

/* primary 主按钮：3D 堆叠阴影，全站唯一（硬规则 5） */
.btn-primary {
  background-color: var(--primary);
  color: #fff;
  border-radius: 50px;
  font-weight: 600;
  box-shadow: 0 5px 0 0 #bdaea0;
  transition:
    background-color 0.15s var(--ease-standard),
    color 0.15s var(--ease-standard),
    box-shadow 0.15s var(--ease-standard),
    transform 0.15s var(--ease-standard);
}
.btn-primary:hover {
  background-color: #3dd4c6;
  transform: translateY(-1px);
  box-shadow: 0 6px 0 0 #bdaea0;
}
.btn-primary:active {
  background-color: #11a89b;
  transform: translateY(2px);
  box-shadow: 0 1px 0 0 #bdaea0;
}
```

`btn-primary` 接入了 **10 处真 CTA**（只在原类上追加 class，背景/圆角/hover 由未分层规则统一接管）：

`404.astro`、`sponsor.astro`、`atom.astro`、`rss.astro`、`posts/[...slug].astro`（赞助按钮×2）、`EncryptedContent.astro`（解锁提交）、`AnimeCard/AnimeDetailModal`、`BilibiliCard/BilibiliDetailModal`。

**刻意不给 3D** 的：分页当前页、筛选器激活态（状态指示非动作按钮）、导航栏 ghost 胶囊（只配柔和影）。

焦点环不用动——全站已有 `outline: 2px solid var(--primary)` 基线（main.css `@layer components`），默认色相下就是薄荷。

### 排版期：Nunito 圆体接入（2 文件 + 6 字体）

现状原为：正文 Latin = Work Sans，**标题链 = Playfair + 思源宋体（衬线）**——与规范「圆体无衬线」完全相反。

2. **`src/config/fontConfig.ts`**：
   - `fontsList` 新增 Nunito 定义（`provider: "local"`，六个 variants 指向上列文件）
   - `selected: ["--font-work-sans", …] → ["--font-nunito", "--font-hanyi-wenhei"]`（拉丁 Nunito，CJK 回退汉仪文黑）

   - `@theme` 的 `--font-sans` → `'Nunito', 'Noto Sans SC', …`

## 三、关键机制与坑（复刻必读）

1. **Tailwind v4 层序是本次的核心手法**：`@layer utilities` > `components` > `base`，而**未分层 > 所有分层**。想让全局换肤盖过模板里散落的工具类（`rounded-*`、`text-black/*`），唯一干净解法是把规则写在层外。反过来，想让 utility 还能覆盖（如 `font-bold`），就必须把规则放进 `base` 层。
2. **`--color-black` / `neutral` / `gray` 三个主题变量是最大杠杆**：改 3 行定义 = 全站 240+ 处冷色自动转暖。新写样式前先想「这属于哪个语义族」，能挂族就不写死。
3. **`data-theme` 属性是双语义**：它同时是「Expressive Code 高亮主题名」（`one-light`/`one-dark-pro`）和「友圈 FCL 样式的明暗信号」。想做规范里的**深巧克力代码块**（`#2b2118`）需要让亮色模式也用暗色语法主题——会破坏友圈桥接，必须先把 EC 主题选择解耦到独立属性（如 `themeSelector: 'html[data-ec-theme]'`）。这是本文搁置的可选工程。
4. **`localStorage.hue` 覆盖默认色相**：站点机制是存储值优先于 `siteConfig`。移植后旧浏览器仍会用旧色相渲染出「奶油底+琥珀主色」的缝合怪，控制台 `localStorage.removeItem("hue")` 后刷新。
5. **grep 会被 Astro 语法骗**：`class:list={["prose …"]}` 里的类名用 `class="..."` 模式搜不到，定位样式来源时优先浏览器探针（getComputedStyle），不要只信文本搜索。
6. **本机 `pnpm` 是 ps1 脚本**，`Start-Process -FilePath "pnpm"` 间歇报「不是有效 Win32 应用」，后台拉起要用 `pnpm.cmd` 全路径。
7. Playwright 截图会等 `document.fonts.ready`，Google Fonts 被墙时永不返回——本机验证截图要么先拦截字体域名，要么走 CDP `Page.captureScreenshot`。
